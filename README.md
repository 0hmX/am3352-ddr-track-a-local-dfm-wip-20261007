# AM3352 DDR3 and RGB888 HDMI

This is a **partially routed work in progress**. Only the provisional DDR_DQS1 and DDR_DQSn1 pair is mounted, with pad-centered transitions to the bottom layer. The remaining 44 DDR signals and the power, ground, HDMI and other connections still need routing; reference planes are not yet mounted. Earlier DDR paths and power/ground feeds remain in `data/` and `layout/` as historical reference and do not describe the active PCB. This board is not fabrication-ready or DDR/HDMI signal-integrity qualified.

## Development

Requires Bun and Python 3.9 or later.

```sh
bun install --frozen-lockfile
bun run dev
```

Open `http://localhost:3020/#file=index.tsx&tab=pcb`. The development script mirrors the active TSX source and watches it for changes. `bun run build` generates the site in ignored `dist/`.

The PCB is organized into 11 native functional subcircuits, each defined in its own file under `subcircuits/`. Each PCB group has a two-dimensional bounding box covering its components on both sides of the board. The current component positions are preserved, so some boxes overlap; the boxes are organization boundaries, not physical keepouts. Run `bun test tests/subcircuit-grouping.test.tsx` to check placement, group bounds and electrical connectivity against the equivalent ungrouped board.

## Routing direction

Use the bus-lanes solver on the physical pad endpoints generated by the native TSX board. For DDR, leave an open corridor in the center, use at least two bends per signal with no direction change above 30 degrees, and place any length-tuning meanders on the outside of the bus. A candidate must be checked for pad and via clearance, continuity, signal spacing, differential-pair geometry, group length matching and reference-plane continuity before it is used. The previous `route:ddr` script is a historical partial reroute of an older stackup; it is not a complete router for the cleared board and should not be applied as-is.

`bun scripts/experiment-ddr-bus-lanes.tsx <top|inner2|inner4|bottom>` runs an exploratory solver pass using the board's physical pads and holes, pad-centered signal vias and a 4 × 7 mm trial center keepout. Set `PAIR_ONLY=1` to try a differential pair independently. `bun scripts/audit-ddr-bus-lanes-experiment.ts <layer> [--pair]` screens a solver result for the trial keepout, at least two turns, a maximum 30-degree direction change, and a 0.20 mm return-arm edge gap; raw solver output may need rounding before it passes. This gap is a provisional design target, not a TI meander specification. `bun scripts/verify-ddr-candidate.tsx <candidate files...>` renders candidates in the native board and checks physical geometry, planned DDR via clearances, coverage and nominal length skew. The scripts do not apply copper, establish external-facing meanders or minimum meander amplitude, check all TI class spacing, or qualify timing and impedance. Results go under ignored `work/ddr/experiments/` and `work/ddr/candidate-verification/`.

The DQS1 pair is a provisional starting point: native geometry and pair-skew screens pass, but the other byte-1 signals have not been matched to it. Its bends use finite-radius curves sampled at no more than 3 degrees per segment transition. To reproduce the present pair, run `PAIR_ONLY=1 bun scripts/experiment-ddr-bus-lanes.tsx bottom`, then `bun scripts/round-ddr-dqs1.ts`. The rounding script is specific to that exact candidate and refuses changed solver output. Independently validate its result before applying changes. The solver may need to move this pair when the full byte is routed. Trials moving the RAM and nearby HDMI arrays did not produce a valid complete byte, so those placement changes were not applied.

The [AM335x datasheet](https://www.ti.com/lit/ds/symlink/am3352.pdf), DDR3 routing tables 7-68 and 7-69, specifies spacing in multiples of the trace width and limits skew by signal group. It does not specify a universal minimum meander amplitude or bend radius. Any such minimum is a separately chosen design constraint, not a TI requirement. Confirm impedance, return paths, fabrication stackup, and timing against the actual board and memory before manufacturing.
