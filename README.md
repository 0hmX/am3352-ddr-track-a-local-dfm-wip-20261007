# AM3352 DDR3 and RGB888 HDMI

This is a **partially routed work in progress**. Twenty-six DDR signals are mounted as provisional bus-lane solver candidates: eight byte-0 data/mask signals on Inner 2, fourteen clock/address/control signals on Top or Inner 4, and DDR_D8/DDR_D12 plus the DDR_DQS1/DDR_DQSn1 pair on Bottom. The other 20 DDR signals and the power, ground, HDMI and other connections still need routing; reference planes are not yet mounted. Earlier DDR paths and power/ground feeds remain in `data/` and `layout/` as historical reference and do not describe the active PCB. This board is not fabrication-ready or DDR/HDMI signal-integrity qualified.

## Development

Requires Bun and Python 3.9 or later.

```sh
bun install --frozen-lockfile
bun run dev
```

Open `http://localhost:3020/#file=index.tsx&tab=pcb`. The development script mirrors the active TSX source and watches it for changes. The file picker shows the main board and the files in `subcircuits/`; `subcircuits/DDR3Preview.tsx` shows the processor, DDR and provisional routes together. `bun run build` generates the site in ignored `dist/`.

The PCB is organized into 11 native functional subcircuits, each defined in its own file under `subcircuits/`. Each PCB group has a two-dimensional bounding box covering its components on both sides of the board. The current component positions are preserved, so some boxes overlap; the boxes are organization boundaries, not physical keepouts. Run `bun test tests/subcircuit-grouping.test.tsx` to check placement, group bounds and electrical connectivity against the equivalent ungrouped board.

## Routing direction

Use the bus-lanes solver on the physical pad endpoints generated by the native TSX board. For DDR, leave an open corridor in the center, use at least two bends per signal with no direction change above 30 degrees, and place any length-tuning meanders on the outside of the bus. A candidate must be checked for pad and via clearance, continuity, signal spacing, differential-pair geometry, group length matching and reference-plane continuity before it is used. The previous `route:ddr` script is a historical partial reroute of an older stackup; it is not a complete router for the cleared board and should not be applied as-is.

`bun scripts/experiment-ddr-bus-lanes.tsx <top|inner2|inner4|bottom>` runs an exploratory solver pass using the board's physical pads and holes, pad-centered signal vias and a 4 × 7 mm trial center keepout. It excludes the mounted provisional traces, so its output must be checked against them before combining routes. Set `PAIR_ONLY=1` to try a differential pair independently. `bun scripts/audit-ddr-bus-lanes-experiment.ts <layer> [--pair]` screens a solver result for the trial keepout, at least two turns, a maximum 30-degree direction change, and a 0.20 mm return-arm edge gap; raw solver output may need rounding before it passes. This gap is a provisional design target, not a TI meander specification. `bun scripts/verify-ddr-candidate.tsx --mounted` screens the checked-in provisional routes; replace `--mounted` with candidate JSON files to screen other routes. The verifier checks physical geometry, planned DDR via clearances, coverage and nominal length skew, and intentionally reports failure while the bus is incomplete. The scripts do not apply copper, establish external-facing meanders or minimum meander amplitude, check all TI class spacing, or qualify timing and impedance. Results go under ignored `work/ddr/experiments/` and `work/ddr/candidate-verification/`.

To explore one layer per DDR group, set `SEPARATE_GROUP=BYTE0`, `BYTE1` or `ADDRESS` when running the experiment. Its default trial assigns BYTE0 to Inner 2, BYTE1 to Bottom and address/control/clock to Inner 4, including the planned via-in-pad lands for all three groups as obstacles. The solver starts without mounted candidate traces; validate any combined output against the full board. Audit a successful output with `bun scripts/audit-ddr-bus-lanes-experiment.ts inner2 --separate-group=BYTE0` (add `--pair` for a pair-only run). Add `--separate-layers` to the verifier to require complete groups on three distinct layers. This trial is not an accepted routing plan: reference planes, via construction, matching and actual clearance still require validation.

The DQS1 pair is provisional: native geometry and pair-skew screens pass, but most byte-1 signals remain unrouted. Its bends use finite-radius curves sampled at no more than 3 degrees per segment transition. `PAIR_ONLY=1 bun scripts/experiment-ddr-bus-lanes.tsx bottom` followed by `bun scripts/round-ddr-dqs1.ts` reproduces the earlier, shorter pair used as the starting point, not the currently mounted tuned pair. The rounding script is specific to that exact candidate and refuses changed solver output.

The eight byte-0 candidates use outside-facing tuning banks; D8, D12 and DQS1 have outside lobes, the clock pair has a small tuning correction, and the address/control routes have no tuning meanders yet. Inner-layer candidates use pad-centered 0.20 mm holes with 0.30 mm pads; the four Top signals connect directly. Together with DQS1, the candidates pass native copper-clearance and connectivity screens, the trial 4 × 7 mm center corridor, the 0.20 mm return-arm gap screen, and the 30-degree turn limit. The eight byte-0 signals currently have approximately 0.648 mm nominal length spread, above the 0.635 mm group target, and three members remain unrouted. Their 39–40 mm planar lengths also substantially exceed the approximately 25.8 mm longest byte-0 endpoint Manhattan distance used for TI's nominal routing target; shorter routes should be investigated. The four routed byte-1 signals have approximately 0.543 mm nominal length spread, below the 0.635 mm target, but seven members remain unrouted. The clock pair's nominal skew is approximately 0.125 mm against a 0.127 mm limit, leaving little margin. The address/control routes require length matching and outside tuning. TI spacing exceptions, differential impedance, return planes, and complete timing still need verification; do not treat these provisional routes as qualified. Future solver runs may need to move them.

A reverse-endpoint bus-lane experiment produced a roughly 25 mm planar DQS0 pair, but it has three clearance conflicts with the mounted byte-0 data lanes. Attempts to rebuild and length-match the whole byte around it did not produce a usable bundle. A placement trial moving RAM 4 mm toward the processor and the nearby clock gate 0.5 mm sideways also passed a placement screen but did not produce a complete routed byte. Neither experiment is mounted.

The [AM335x datasheet](https://www.ti.com/lit/ds/symlink/am3352.pdf), DDR3 routing tables 7-68 and 7-69, specifies spacing in multiples of the trace width and limits skew by signal group. It does not specify a universal minimum meander amplitude or bend radius. Any such minimum is a separately chosen design constraint, not a TI requirement. Confirm impedance, return paths, fabrication stackup, and timing against the actual board and memory before manufacturing.
